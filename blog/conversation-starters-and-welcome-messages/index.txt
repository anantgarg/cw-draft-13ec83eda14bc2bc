15:T1570,<p>Welcome messages and conversation starters now use the same kind of rule table as proactive messages. Each has its own prioritized rules. The matching rule runs. I pinned this direction in #rnd on 28 Sep 2026: a welcome message shows the first match, and starters fill a quota across matching rules, keyed on the page and product the shopper is on.</p>
<p>In the dashboard, operators use the Greeting &amp; starters area to create an ordered list of greeting rules and conversation starter rules for a workspace. A rule can run across every channel, or only on the channels the merchant selects.</p>
<p>A shopper on a product page can see an opening that fits that product. Someone arriving through an ad can see a different one. A visitor who has added an item to the cart can be offered a starter that refers to the matched item. Starters are meant to key on the page and the product the shopper is looking at, so a product page can offer chips that belong to that product.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/conversation-starters-and-welcome-messages/01-conversation-starter-chips.png" alt="Conversation starter chips in the current design reference." /><figcaption>Conversation starter chips in the current design reference.</figcaption></figure></p>
<h2 id="rules-that-follow-the-visit">Rules that follow the visit</h2><p>Each rule can check the page, ad source, device, signed-in state, cohorts, activity during the current visit or a tracked event. Event rules can also inspect lists. An operator can check whether any cart item matches a condition, and use details from that matched item in the message.</p>
<p>Operators type the greeting or the starter chips directly. They can also insert visitor, page or matched-item details. When the opening needs more flexibility, an AI agent or a selected model can write the message from the operator&#39;s instructions. The operator supplies a fallback for that generated message, so the opening still has useful copy if the writing does not complete.</p>
<p>Order matters. Crossword checks greeting rules from top to bottom, and the first match decides the greeting. Starter rules work the other way: matching rules can top up the set of suggested questions until the configured space is filled. The merchant keeps control of the main welcome, and several relevant prompts can still contribute to the choices under it.</p>
<p>The starter chips themselves also got a visual pass: shadow, color, border and the brand font, so they sit in the same type and color system as the rest of the widget.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/conversation-starters-and-welcome-messages/02-suggestion-chip-cards.png" alt="Suggestion chip cards in the current design reference." /><figcaption>Suggestion chip cards in the current design reference.</figcaption></figure></p>
<h2 id="the-opening-stays-connected-to-the-conversation">The opening stays connected to the conversation</h2><p>Before the shopper sends a message, the opening can follow the page and the visit. A page change or a relevant tracked event can produce a better match. Once the shopper sends the first message, Crossword fixes the opening for that conversation. The greeting the shopper saw becomes part of the conversation&#39;s context, and it stays there if the browser later moves to another page.</p>
<p>If no greeting rule matches, the widget uses its existing greeting. If no starter rule matches, it uses its existing chips. If the rule route is unavailable, the widget keeps that existing opening, and chat remains available.</p>
<p>The feature is controlled per workspace. An operator turns on greeting rules for the workspace. The dashboard then shows the Greeting &amp; starters area, and the widgets begin asking for the rule-driven opening. Workspaces without it turned on continue to use their existing greeting and chips.</p>
<h2 id="starters-before-and-after-the-first-answer">Starters before and after the first answer</h2><p>Starter chips help a shopper begin. Follow-up chips help them continue after an answer. They sit at different moments, and a channel can treat them separately.</p>
<p>Crossword can show up to 10 follow-up chips, and the model can choose to show fewer. A channel also controls how repeated follow-up chips are handled. By default, a chip already shown earlier in the conversation is removed. An operator can switch that behavior off for a channel, in which case every chip the model writes is shown as written. The model still receives the earlier chips in its context.</p>
<p>The 10-chip ceiling and the repeat-chip switch are channel settings. They sit next to the starter rules. They apply after the first answer, once the conversation is already under way.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/conversation-starters-and-welcome-messages/03-home-welcome-nudge.png" alt="A proactive welcome nudge from the current design reference." /><figcaption>A proactive welcome nudge from the current design reference.</figcaption></figure></p>
<p>These starter and greeting rules sit on the same structure as proactive messages, and they work per feature. The merchant writes the rules, chooses the channels and turns the workspace setting on. Shoppers see the first matching welcome, a filled set of starter chips and, after an answer, follow-up chips under the channel&#39;s ceiling and repeat switch.</p>
