15:T164a,<p>We built Crossword to help ecommerce teams create AI shopping assistants that can handle real customer conversations. A large part of that work happens before a shopper ever sends a message. Operators need to test how an agent behaves, inspect the result and decide which configuration deserves to become the draft.</p>
<p>The Playground already gave operators a place to chat with the agent they were editing. It ran the persisted draft configuration through the same orchestration path used by the product, streamed the reply and kept the test conversation separate from shopper conversations. That made a draft testable inside the editor.</p>
<p>The next problem was comparison.</p>
<p>Testing one configuration at a time forces the operator to keep too much context in their head. Run a prompt, remember the response, change the model or its configuration, run the prompt again and then try to compare results that appeared at different times. Small differences in instruction following, tone or completeness become harder to judge. Repeating that loop also makes it easy to lose track of the configuration behind a response.</p>
<p>Playground model comparison puts those runs together. An operator can select multiple model variants, including the same model with different configurations, run them against the same prompt and review the results side by side. Once the operator chooses the configuration they want, they can apply it to the draft.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/playground-model-comparison/01-compare-models.png" alt="The current design reference for comparing model runs in the agent Playground." /><figcaption>The current design reference for comparing model runs in the agent Playground.</figcaption></figure></p>
<h2 id="hold-the-prompt-steady">Hold the prompt steady</h2><p>Model evaluation gets noisy when the test changes between runs. Compare mode keeps the test steady. The prompt is shared across the selected variants. Each result remains attached to the configuration that produced it. The operator can read the responses in the same view instead of reconstructing the experiment from memory.</p>
<p>This matters for shopping assistants because quality is contextual. A response can be accurate and still miss the job. The operator may be checking whether the agent follows its instructions, keeps the intended tone or gives a complete answer for the scenario being tested. Side-by-side output gives that judgment a clearer surface.</p>
<p>The feature also supports comparing different configurations of the same model. That detail is important. Model choice is only one part of an agent setup. Sometimes the useful experiment is a configuration change while everything else stays fixed. Compare mode keeps both kinds of tests in one workflow.</p>
<h2 id="keep-testing-connected-to-editing">Keep testing connected to editing</h2><p>An evaluation tool loses value when its result has to be copied back into another screen. The Playground lives with the agent editor and comparison ends with an action on the draft. After reviewing the runs, the operator can apply the selected configuration to the draft and continue editing from there.</p>
<p>That makes the evaluation loop concrete:</p>
<ol>
<li>Open the agent in the dashboard.</li>
<li>Select the model variants or configurations to test.</li>
<li>Send the same prompt to those variants.</li>
<li>Review the runs side by side.</li>
<li>Apply the chosen configuration to the draft.</li>
</ol>
<p>The surface is for operators and FDEs working on an agent. Shoppers never see the comparison view. They see the eventual behavior of the shopping assistant after the team has tested its configuration.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/playground-model-comparison/02-shopping-assistant-context.png" alt="The Shopping Assistant editor provides the dashboard context around the Playground." /><figcaption>The Shopping Assistant editor provides the dashboard context around the Playground.</figcaption></figure></p>
<h2 id="build-judgment-into-the-workflow">Build judgment into the workflow</h2><p>There is a temptation to turn model selection into a fixed answer. In practice, the right configuration depends on the agent, its instructions and the conversation being tested. Teams need a fast way to inspect real outputs with the variables made visible.</p>
<p>Playground comparison gives the operator that control without moving the work out of Crossword. The test prompt, the candidate configurations, the responses and the draft stay connected. The operator still makes the decision. The product makes the evidence easier to inspect and the decision easier to carry forward.</p>
<p>We also kept the scope focused on the dashboard workflow. This release extends the existing text Playground with side-by-side runs and draft application. Shopper-facing behavior stays unchanged. The current design reference shows comparison as part of the agent workspace, alongside the surrounding editor used to configure the shopping assistant.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/playground-model-comparison/03-agents-list.png" alt="The Agents list is the entry point to the agent workspace in the current design reference." /><figcaption>The Agents list is the entry point to the agent workspace in the current design reference.</figcaption></figure></p>
<p>The result is a shorter path from a configuration idea to an informed draft. An operator can run a controlled comparison, inspect the responses together and carry the selected configuration into the agent they are already editing.</p>
