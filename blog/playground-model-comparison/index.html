Test agent configurations side by side in the Playground

21 July 2026Released
Hold the prompt steadyKeep testing connected to editingBuild judgment into the workflow

We built Crossword to help ecommerce teams create AI shopping assistants that can handle real customer conversations. A large part of that work happens before a shopper ever sends a message. Operators need to test how an agent behaves, inspect the result and decide which configuration deserves to become the draft.

The Playground already gave operators a place to chat with the agent they were editing. It ran the persisted draft configuration through the same orchestration path used by the product, streamed the reply and kept the test conversation separate from shopper conversations. That made a draft testable inside the editor.

The next problem was comparison.

Testing one configuration at a time forces the operator to keep too much context in their head. Run a prompt, remember the response, change the model or its configuration, run the prompt again and then try to compare results that appeared at different times. Small differences in instruction following, tone or completeness become harder to judge. Repeating that loop also makes it easy to lose track of the configuration behind a response.

Playground model comparison puts those runs together. An operator can select multiple model variants, including the same model with different configurations, run them against the same prompt and review the results side by side. Once the operator chooses the configuration they want, they can apply it to the draft.

Hold the prompt steady

Model evaluation gets noisy when the test changes between runs. Compare mode keeps the test steady. The prompt is shared across the selected variants. Each result remains attached to the configuration that produced it. The operator can read the responses in the same view instead of reconstructing the experiment from memory.

This matters for shopping assistants because quality is contextual. A response can be accurate and still miss the job. The operator may be checking whether the agent follows its instructions, keeps the intended tone or gives a complete answer for the scenario being tested. Side-by-side output gives that judgment a clearer surface.

The feature also supports comparing different configurations of the same model. That detail is important. Model choice is only one part of an agent setup. Sometimes the useful experiment is a configuration change while everything else stays fixed. Compare mode keeps both kinds of tests in one workflow.

Keep testing connected to editing

An evaluation tool loses value when its result has to be copied back into another screen. The Playground lives with the agent editor and comparison ends with an action on the draft. After reviewing the runs, the operator can apply the selected configuration to the draft and continue editing from there.

That makes the evaluation loop concrete:

  1. Open the agent in the dashboard.
  2. Select the model variants or configurations to test.
  3. Send the same prompt to those variants.
  4. Review the runs side by side.
  5. Apply the chosen configuration to the draft.

The surface is for operators and FDEs working on an agent. Shoppers never see the comparison view. They see the eventual behavior of the shopping assistant after the team has tested its configuration.

Build judgment into the workflow

There is a temptation to turn model selection into a fixed answer. In practice, the right configuration depends on the agent, its instructions and the conversation being tested. Teams need a fast way to inspect real outputs with the variables made visible.

Playground comparison gives the operator that control without moving the work out of Crossword. The test prompt, the candidate configurations, the responses and the draft stay connected. The operator still makes the decision. The product makes the evidence easier to inspect and the decision easier to carry forward.

We also kept the scope focused on the dashboard workflow. This release extends the existing text Playground with side-by-side runs and draft application. Shopper-facing behavior stays unchanged. The current design reference shows comparison as part of the agent workspace, alongside the surrounding editor used to configure the shopping assistant.

The result is a shorter path from a configuration idea to an informed draft. An operator can run a controlled comparison, inspect the responses together and carry the selected configuration into the agent they are already editing.
