18:T1887,<p>I have seen the same problem appear in every serious shopping agent project: the useful answer lives in merchant data, while the agent starts with a prompt.</p>
<p>A catalogue can sit in one system. Order data can sit in another. An operator may know the exact query that answers a common shopper request. The agent still needs a reliable way to reach that information with the right access.</p>
<p>We built Data Tables in Crossword to make that connection explicit. Crossword is an AI shopping assistant for ecommerce. Data Tables gives the people operating it a workspace for connecting data, inspecting rows, preparing queries and deciding what each agent can use.</p>
<p>The surface lives in the merchant dashboard. Shoppers never have to understand the table behind an answer. They experience the result when the agent can use current merchant data during a conversation.</p>
<h2 id="a-working-surface-for-merchant-data">A working surface for merchant data</h2><p>An operator can create a table, define its columns and work with its rows from the dashboard. The rows grid supports inline editing, type-aware inputs, adding and deleting rows, sorting and search. Locked tables remain readable while writes are blocked.</p>
<p>The column setup keeps a human-facing display name alongside a safe database identifier. When someone adds a column called &quot;Full Name,&quot; for example, the interface previews the stored identifier before the change is made. This small detail matters when the same table has to work for an operator, a query and an agent.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/data-tables/01-rows-editable.png" alt="The current Crossword dashboard design reference showing editable table rows." /><figcaption>The current Crossword dashboard design reference showing editable table rows.</figcaption></figure></p>
<p>Data can also arrive through connectors. The shipped file-upload flow accepts a JSON document, detects fields and lets the operator map them into a managed table. It reuses the same column inference, typing, indexing and table registration path used by JSON ingestion. The resulting table returns to the same workspace surface as manually managed data.</p>
<h2 id="save-the-query-once">Save the query once</h2><p>Raw rows are useful for inspection. Agents need a narrower contract.</p>
<p>Stored queries let an operator define that contract. A query has declared parameters and Crossword validates the inputs before execution. System values such as the workspace, agent, run and contact are injected by the runtime. The agent cannot replace them through its own arguments.</p>
<p>The dashboard includes an editor and a playground. Operators can preview reads and test writes. Write previews roll back by default, with an explicit path to commit. Read results can be capped and executions produce audit records with the mode, source, tables and row count.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/data-tables/02-stored-query-edit.png" alt="The current Crossword dashboard design reference showing a stored query in edit mode." /><figcaption>The current Crossword dashboard design reference showing a stored query in edit mode.</figcaption></figure></p>
<p>The next step is binding. In an agent&#39;s Data section, an operator attaches table access and stored queries. Table access can be assigned by action, including find, insert, update and delete. Query bindings control read or write mode, delivery as a tool or prompt context, cadence for prompt delivery and an optional row cap.</p>
<p>That last part changes how I think about prompts. A prompt can refer to a stored query without carrying the merchant&#39;s data inside the prompt itself. Crossword resolves the binding at runtime. Tool bindings are exposed to the agent as executable tools. Prompt bindings run on their configured cadence and place the result into the assembled prompt.</p>
<h2 id="search-by-meaning-and-derive-useful-columns">Search by meaning and derive useful columns</h2><p>Some tables need a search layer. An operator can enable semantic search for a table and choose the columns that should be embedded. Crossword maintains row embeddings asynchronously, including a backfill when search is enabled and incremental updates as data changes. The agent receives a search tool only for a table it has been granted.</p>
<p>Search returns live rows after finding relevant records. That keeps the index focused on retrieval while the table remains the source used for the result.</p>
<p>Enrichment adds derived columns to the same data model. An operator chooses source columns and the derived columns to generate, reviews a projected call count and confirms the backfill. The pipeline can then process changes as they arrive. Enrichment and semantic search are optional controls at the table level.</p>
<h2 id="access-belongs-in-the-data-path">Access belongs in the data path</h2><p>Prompt instructions are a weak place to enforce data permissions. Crossword carries permissions into query registration and execution.</p>
<p>Each workspace has isolated data-plane roles. Each agent receives only the table actions and stored queries assigned to it. For a table linked to a contact, PostgreSQL row-level security scopes agent reads and writes to the verified contact being served. The runtime sets that verified identity in the database session. An anonymous or unverified request has no contact scope, so the policy fails closed.</p>
<p>Operators still need to manage the complete table. Dashboard row operations use a separate workspace analyst role while agent paths continue through the scoped roles. This preserves an operator&#39;s working view without weakening the agent boundary.</p>
<p>The same system records data access for review. Operators can filter access logs and follow a record back to the related agent run. Together, grants, bindings, database roles, row policies and audit records make table access a product setting with an execution path behind it.</p>
<p>Operators can inspect the source, shape the query, assign the capability and review its use from the dashboard. The shopper receives an answer grounded in the data that the agent was allowed to reach.</p>
