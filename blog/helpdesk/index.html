HelpDesk gives support operators one workspace for every conversation

21 July 2026Released
One inbox with clear groupsPrivate notes stay privateResolve means the conversation is closedA workspace for the desk

We built Crossword to help shoppers get useful answers while they are deciding what to buy. That front line can handle a lot. Some conversations still need a person, and the quality of the experience depends on what happens when a support operator opens the conversation.

HelpDesk gives that operator a working inbox inside the Crossword dashboard. It brings the conversation list, full thread and context rail into one workspace. The operator can see what needs attention, work through active conversations and close the ones that are finished.

The important detail is continuity. A person should enter a conversation with the context already in front of them. Asking a shopper to repeat the exchange creates work at the exact moment they need help. The inbox is wired to the same handoff workflow that carries the conversation, so the desk can continue from the existing thread.

One inbox with clear groups

Support work becomes harder when every conversation looks equally urgent. HelpDesk organizes the inbox into grouped views for conversations, items that need attention and status. It also includes a resolved section for completed work.

The layout is deliberately familiar: conversation groups and a list on the left, the selected thread in the center and a context rail beside it. An operator can move between conversations while keeping the active exchange visible. Contact names are surfaced in the list so the desk can identify the person behind each thread.

Permissions follow the same rules on the screen and the server. Actions in the dashboard are shown according to the operator's abilities, while server guards enforce the same access. That matters in a shared support workspace, where a visible button and an allowed action need to agree.

Private notes stay private

Operators often need to leave context for each other. HelpDesk adds internal notes directly to the conversation transcript. A note includes its author and remains visible in the dashboard for the support team.

The privacy boundary is explicit. Internal notes are never relayed to the shopper's widget. They are also excluded from the AI's conversation history. The widget serialization was narrowed so these notes cannot reach the customer, and the underlying action has its own handoff:note permission for support roles.

This lets an operator record useful working context in the place where the next operator will look. The customer conversation stays clean, and the AI continues from customer-visible history without absorbing private desk notes.

Resolve means the conversation is closed

HelpDesk treats Resolve as a terminal action. Once an operator resolves a conversation, it moves into the resolved group. The dashboard keeps a resolved marker in the operator transcript so the desk has a clear record of the outcome.

The shopper sees a closed-state bar instead of an extra resolution message in the transcript. The chat input is locked and prompts them to start a new conversation. If the shopper does start again, that new conversation becomes the next unit of work.

That behavior avoids an ambiguous state where a thread looks closed to the operator while the shopper can keep adding messages to it. The workflow has one clear end. It also supports a silent transparency setting, which suppresses customer-visible join and handback announcements when that setting is configured.

A workspace for the desk

HelpDesk also moves its configuration into a Workspace settings tab and adds Inbox near the top of the dashboard navigation. These details make the support workflow part of the merchant's everyday operating surface.

For the team at the desk, the result is straightforward. They can find conversations by group, read the thread with its context, reply, add a private note when their role allows it and resolve completed work. For the shopper, the same workflow preserves the conversation they already had and makes the closed state clear when the operator finishes.

We designed the workspace around the handoff itself: preserve the thread for the person taking over, protect internal context and give both sides an unambiguous end state.
