15:T1592,<p>Operators can now filter the Contacts list, tick the contacts they want and export them as a CSV. The export runs as a background job. The file lands in private storage, and the browser downloads it automatically when it is ready.</p>
<p>The flow stays with the list the operator is already looking at. Filter it, choose the rows and start the export. Contact export is turned on per workspace. Once it is on, and the operator&#39;s role includes the <code>contact:export</code> permission, the action is available from Contacts. Workspaces that leave it off keep the Contacts list as it was, without an export action.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/contact-export/01-contact-selection.png" alt="Design reference for multi-select on a dashboard list, with a caption noting that Storybook has no Contacts export screen yet." /><figcaption>Design reference for multi-select on a dashboard list, with a caption noting that Storybook has no Contacts export screen yet.</figcaption></figure></p>
<h2 id="start-with-the-list">Start with the list</h2><p>An operator may need the active contacts with a verified email, or the disabled contacts with a verified phone, or another slice that belongs in a file outside the dashboard. The Filter menu is how that slice is named. It has two groups. Status includes Active, Disabled and Deleted. Verification includes Unverified, Identity, Email and Phone, matching the language in the Verified column. The list opens with Active and Disabled contacts. Clear and Apply make the filter state explicit, and chips keep changed rules visible after the menu closes.</p>
<p>Search and filters describe the contacts in view. Selection describes which of those contacts belong in the file. An operator can tick individual rows, or use the header checkbox to select the current page. From there, the list offers &quot;Select all N contacts&quot; for every match. Unticking a row leaves that contact out of the larger selection.</p>
<p>The Export CSV action appears only after at least one contact is selected.</p>
<h2 id="let-the-export-continue-in-the-background">Let the export continue in the background</h2><p>Crossword starts a background job on the data-sync worker and writes the completed CSV into a private bucket. The operator can keep moving through the dashboard while that happens. A progress card follows them across the dashboard with its percentage, a link to the Exports tab and a dismiss control. Dismissing the card only hides it. It does not cancel the job, and it does not stop the finished file from downloading.</p>
<p>When the file is ready, the CSV downloads automatically. The Exports log can show a running state such as &quot;Running · 42%&quot; while the job is in progress.</p>
<h2 id="keep-a-record-of-every-run">Keep a record of every run</h2><p>The Exports tab lives beside Contacts. It lists every export for the workspace with the filters used, the file format, the contact count, the status, the person who ran it and a Download action when the file is ready. A running row can show a percentage next to its status, so the operator has a record of the job they started, not only a spinner on the page they left.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/contact-export/02-contact-exports-log.png" alt="Design reference for a background run log, with a caption noting that Storybook has no Contacts Exports tab yet." /><figcaption>Design reference for a background run log, with a caption noting that Storybook has no Contacts Exports tab yet.</figcaption></figure></p>
<p>Each click on Download requests a fresh link that lasts five minutes. The underlying file stays in private storage. The short link gives the operator a practical download window, and it is not a permanent public URL. A teammate can see what was run, who ran it and whether it completed. An operator who dismissed the progress card can return to the same record.</p>
<h2 id="treat-bulk-contact-data-as-a-privileged-action">Treat bulk contact data as a privileged action</h2><p>Access follows two gates. The workspace must have contact export turned on, and the operator&#39;s role must include the <code>contact:export</code> permission. Admins and members receive that permission by default. Workspace administrators can grant it to a custom role.</p>
<p>Exports are available through signed-in dashboard sessions. API keys and MCP tokens are refused.</p>
<p>The file itself is written as standard CSV. Spreadsheet formula cells are neutralized, and E.164 phone numbers are preserved. Selection has a configured maximum. API responses and audit records use counts, and they do not record selected contact IDs or search text.</p>
<p>Erasure is part of the same design. When Crossword processes the relevant Shopify customer or shop redaction, it removes export files for the workspace, cleans up unfinished uploads, marks those records as removed and clears the matching contact&#39;s name, email and phone before recording the request as processed. That cleanup is limited to the erased shopper and the workspace&#39;s export files. It is not a general delete-everything control on the Exports tab.</p>
<p>The filters define the group. Selection handles the exceptions. Background progress keeps the dashboard available, and the Exports tab keeps the run on record. The operator asks for a file from the same list they were already using, and the log is where that request lives afterwards.</p>
