Proactive messages now stand as a stack

5 October 2026Docs
A stack of up to threeOpening a messageMerchants turn the stack on

When several proactive messages match a shopper, they stand as a stack. On the closed chat bar, answer cards and store messages wait together, up to three at a time.

I pinned this direction in #rnd on 25 Aug 2026. The work that followed lives on the closed launcher: a stack that survives a page change and a refresh, a cap of three and a single smooth slide when the shopper taps one.

Crossword already had proactive (store) messages, which a merchant writes as rules that fire for a shopper on the site. This post is about what happens when more than one of those messages, or an answer card from a closed-bar turn, is waiting at once.

A stack of up to three

The chat can stay closed. Answer cards and store messages stand on the launcher as a short stack. The cap is three. After a refresh, or after the shopper moves to another page, the same stack is still there.

If the merchant lowers that cap, the extras are pushed out by receipt. A card that has been pushed out stays out across tabs.

Each store message still follows its own rule. A quiet notification dot does not turn into a card, and it does not hide the other messages in the stack. Only one badge shows. When the channel's closed-launcher badge is set to count, a number appears over the stacked cards. When it is set to dot, the cards stand without that number.

Only the newest card is announced to screen readers. The cards tucked behind it are inert. Pressing Enter fans a gathered stack so the shopper can reach a message that is not at the front. A link on a card that is not at the front still opens from that tap.

A store message that is sent again updates in place. It does not add a duplicate card. The visible stack stays at the cap.

Opening a message

A tap opens the message in one smooth slide. The card stands until the chat is ready, then the widget opens once. A second tap while that chat is being created is ignored.

When the shopper opens the chat, standing store messages appear according to each rule's "Chat open" setting. One reply can answer every store message that is standing for that chat. Those replies are saved in the order the messages arrived.

Starter chips can still be asked without opening the chat. The thinking pill that shows while the agent works on a closed bar, and the card that lands when that answer is ready, are described in the closed-launcher post. Those answer cards join this same stack.

Merchants turn the stack on

The stack is off by default. It sits behind the same per-channel closed-launcher settings as the rest of the closed-bar behaviour. A merchant who wants the stack turns that closed-launcher behaviour on for the channel.

With those switches off, the shopper still sees a single store-message slot. A message that takes that slot is settled by receipt, the way it was before this work. The stack itself and the count over the cards only apply once the merchant turns the closed-launcher behaviour on. With that switch on, a tapped store message does not play a chime.

Older widget bundles are unaffected. The additions are optional: a standing-message read, a way to mark a store message as evicted and the events used to keep the stack in step. A site that has not stored this state does not open a stack.

When an answer card is ready to join the stack, it waits for the current unfold to finish.

The same settings cover how a standing message appears once the chat is open, and whether the launcher shows a count or a dot over the cards. The cap of three is the default stack the shopper sees. Lowering it evicts the extra cards by receipt, as above, and that eviction is kept across tabs.

This sits alongside the earlier proactive-messages work, which is how a merchant writes the rules, and alongside closed-bar thinking, which is how an answer can start while the chat is closed. The stack is where those messages and cards wait.
