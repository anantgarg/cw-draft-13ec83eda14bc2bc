15:T13e6,<p>Merchants now control which storefront pages show the Crossword widget. They can keep it across the whole site and hide it on a few pages, or limit it to a selected set of pages. A merchant asked us for a simple version of this: keep the assistant off checkout. That is now a page rule.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/blacklist-whitelist-pages/01-style-tab-pages.png" alt="The Style tab with page visibility controls in the current design reference." /><figcaption>The Style tab with page visibility controls in the current design reference.</figcaption></figure></p>
<h2 id="set-page-visibility-from-the-style-tab">Set page visibility from the Style tab</h2><p>The controls live in Style, under Launcher visibility and Pages. There are two lists: Show only on, and Hide on.</p>
<p>Use Show only on when the assistant belongs in a defined part of the store. A merchant can show it on product paths and leave the rest of the storefront without it. An empty Show only on list means Every page, which is the normal site-wide behavior.</p>
<p>Use Hide on for exceptions. A rule such as Starts with <code>/checkout</code> keeps the widget away from checkout and any page below that path. The empty state is No pages hidden. If a page matches both lists, Hide on wins.</p>
<p>Each list accepts up to 20 rules, and each pattern can contain up to 512 characters. Four match types cover the usual ways storefronts organize URLs: Starts with, Contains, Is exactly and Matches regex.</p>
<p>A pattern beginning with <code>/</code> applies to that path on any domain. A full <code>https://</code> address applies to that site. For Starts with and Is exactly, Crossword requires one of those two forms. Save and Publish refuse a value such as <code>shop.com/checkout</code>, because it is missing the address scheme and does not begin with <code>/</code>.</p>
<p>Is exactly is built around how people think about a page. It ignores a trailing slash, a URL fragment and the query string. If the rule itself includes <code>?</code>, the query string becomes part of the match. A clean page rule can survive ordinary tracking parameters, and a deliberately specific address still matches when the rule includes the query.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/blacklist-whitelist-pages/02-style-sidebar.png" alt="A focused view of the Style workspace used to configure where the widget appears." /><figcaption>A focused view of the Style workspace used to configure where the widget appears.</figcaption></figure></p>
<h2 id="test-the-result-before-publishing">Test the result before publishing</h2><p>The editor includes Test a page, which checks a pasted address with the same matcher the widget uses. It reports whether that page is shown, hidden because it matches Hide on, or hidden because it falls outside Show only on.</p>
<p>Crossword also checks known pages attached to the channel&#39;s agent. If known pages match both lists, the editor warns that they will be hidden. If a Show only on list matches none of the known pages, Crossword asks for confirmation before saving.</p>
<p>Rules are part of the published appearance. A merchant can draft and test changes, then Publish when the setup is ready. Shoppers receive the new rules on their next page load. Page visibility does not travel over the live connection, so an unpublished draft does not alter an active storefront. Rolling back an appearance version does not re-check page rules.</p>
<h2 id="hidden-means-the-whole-widget-is-gone">Hidden means the whole widget is gone</h2><p>On a hidden page, Crossword removes the chat window. The launcher disappears, an open chat is removed and proactive messages do not appear. If the store has its own button wired to <code>CrosswordAgent.open()</code>, that call does nothing on the hidden page.</p>
<p>Tracking continues. The shopper remains the same visitor. When they move back to an allowed page, the widget can return with the same conversation.</p>
<p>The widget also skips the early chat-code download on a page that the rules have already hidden, so the page gets the visibility decision without fetching a chat experience it will not show.</p>
<p>Regex is available for stores whose URL structures need it. Crossword runs those patterns through a linear-time engine, loaded only for stores that use a regex rule. A setup can contain at most five regex rules and at most 50 repeats across them. If that engine cannot load, regex rules are skipped and the widget shows.</p>
<p>The regex engine is loaded from a separate chunk, only when a store actually uses a regex rule, and it runs in linear time. Stores that stay with Starts with, Contains and Is exactly never download it.</p>
<p>Most merchants can stay with paths and those three plain-language match types. A checkout exception takes one Hide on row. A product-only setup takes a short Show only on list. The editor, including Test a page and the overlap warnings, is in the same Style tab merchants already use to shape the widget.</p>
