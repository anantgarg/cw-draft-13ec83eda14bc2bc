15:T157b,<p>Shopping often starts with an image. Someone sees a jacket on the street, saves a product screenshot or takes a photo of something already in their home. Asking them to translate that image into the right search terms adds work before the conversation has even started.</p>
<p>We built image input into Crossword so a shopper can bring the photo directly into the conversation. They can choose an image, paste it or drag it into the chat composer. The image is staged as a thumbnail, uploaded and shown in the transcript with the rest of the conversation.</p>
<p>That simple interaction required work across the widget, upload path, agent runtime and merchant controls. The useful part is what happens after send: Crossword turns the image into context the shopping agent can use with the same catalogue tools it already has.</p>
<h2 id="from-pixels-to-catalogue-search">From pixels to catalogue search</h2><p>An uploaded image goes through one shared ingress path. The upload is validated, its metadata is stripped and HEIC files are normalized to JPEG. Processing then produces structured extraction text for the agent. The extraction contract can be defined for each channel, including the fields to extract, which fields are required and custom instructions.</p>
<p>This structure matters in commerce. A shopper rarely needs a generic description of a photo. The agent needs useful attributes that can become catalogue search input. A photo can yield details such as the attributes configured by the merchant, then the agent can pass that context into the existing <code>search_&lt;table&gt;</code> catalogue tool and return matching product cards.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/image-upload-visual-understanding/01-channel-images-overview.png" alt="The channel Images settings in Crossword's current design reference." /><figcaption>The channel Images settings in Crossword's current design reference.</figcaption></figure></p>
<p>The agent receives the extraction text. It can also receive the image pixels when its model supports vision. That hybrid path gives the runtime a consistent structured representation while preserving direct visual context for models that can use it. Recent image context can be replayed on follow-up turns, so a shopper can continue asking about the same photo without attaching it again.</p>
<p>The same path also supports questions about an image and text extraction from an image. The conversation stays in one thread and the image becomes part of the agent&#39;s working context.</p>
<h2 id="merchant-control-over-extraction">Merchant control over extraction</h2><p>Different catalogues need different visual attributes. A furniture store and an apparel store will define useful image context differently. We put that configuration on the channel&#39;s Images tab in the Crossword dashboard.</p>
<p>Merchants can enable image input, select the extraction model and configure its reasoning setting when that model supports one. They can define extraction fields, mark required fields and provide custom instructions. They can also set limits and an extraction wait budget for the channel.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/image-upload-visual-understanding/02-channel-images-fields.png" alt="Extraction controls on the channel Images tab in Crossword's current design reference." /><figcaption>Extraction controls on the channel Images tab in Crossword's current design reference.</figcaption></figure></p>
<p>The wait budget handles a practical runtime tradeoff. Image extraction runs asynchronously. When an extraction is still pending, the run can show &quot;Looking at your photo…&quot; for the configured window and then proceed. The composer has matching upload, error and retry states, so the shopper gets a clear path when an upload needs attention.</p>
<p>The dashboard also gates reasoning controls to the selected model&#39;s capabilities. A model without a reasoning option does not expose a reasoning picker. Required flags on extraction fields survive the save and load cycle. These details keep the configuration aligned with what the runtime can actually honor.</p>
<h2 id="traceable-image-context">Traceable image context</h2><p>Visual input adds another layer to an agent run, which makes traceability more important. AgentOps records whether image input was included, whether image context was replayed and how many image parts were sent on each model call.</p>
<p>That gives a team evidence for the important handoffs. They can see the attachment turn, inspect when the runtime included visual context and follow the same image into later turns. The trace reflects both the structured extraction and direct image delivery used by the run.</p>
<p>We also paid attention to the chat mechanics around the feature. The staged thumbnail tray, drag target and progress states live inside the composer. Height changes are interruptible and the sheet keeps a stable position when a staged image is sent. Those details prevent the interface from jumping at the moment the shopper expects an answer.</p>
<p>For shoppers, the resulting flow is direct: attach a photo, send it and continue the conversation. For the agent, the photo arrives as usable context that can feed catalogue search, product cards and follow-up answers. For merchants, the Images tab defines what visual information the agent should extract and how that work should run.</p>
