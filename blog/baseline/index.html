The first release of Crossword

27 May 2026Initial release
The merchant sideThe shopper sideSeeing the run

On 27 May 2026, we shipped the first usable version of Crossword, an AI shopping assistant for ecommerce. We called the milestone M7.v0, or the demo bar. It gave our team one complete path from a merchant setting up an agent to a shopper receiving an answer on the merchant's site.

The release was an internal, FDE-operated platform. Our FDEs used it to configure customer workspaces and get the assistant running. The Crossword.ai project stayed open while we hardened that foundation and built out the dashboard. We marked the project Released on 20 Jul 2026 at 14:12 IST.

Those dates describe two useful points in the same release. 27 May is when the end-to-end system first worked. 20 Jul is where we drew the boundary around the core Crossword platform. I use that boundary here because several distinct product features followed with their own releases.

The merchant side

The dashboard started with email and password authentication, workspaces and role-based access. Inside a workspace, an operator could create and publish two kinds of agents: a Master agent and Worker agents.

The Master agent was the front desk. It accepted the shopper's message and selected the right Worker using routing rules, semantic similarity and a model fallback. Each Worker carried its own purpose, instructions, model and attached skills or knowledge.

The agent editor showed those operating details. An operator could configure routing rules for the Master, attach skills and knowledge to a Worker, publish a version and reopen the saved configuration. We also created a default agent when a workspace was provisioned.

Channels connected that setup to a website. An operator could bind a published agent to a web widget, copy its widget key, set allowed origins and remove the binding. The widget shipped as a vanilla JavaScript embed and as a React wrapper.

Knowledge was part of the first platform. Operators could create a knowledge base, add sources, attach it to an agent and test retrieval. The dashboard had a knowledge list, a creation flow, detail views and a playground. Further search and connector work belongs to later stages of the product.

The dashboard also included contacts, workspace settings and a workspace-wide view of conversations. Settings covered workspace details, members, authentication and keys, memory, context variables and MCP configuration. The core platform also included data tables and prompt context.

The shopper side

The merchant embedded a chat widget on the site. The shopper asked a question. Crossword opened a session, sent the message to the entry agent and rendered the answer in the chat.

The run orchestrator resolved the published entry agent and version. The Master routed the request to a Worker. The Worker called a model through a tool-use loop and could query attached knowledge. Messages and trace events were persisted as the run progressed.

The 27 May 2026 acceptance test exercised that entire path. Our team logged in, created and published a Worker, created and published a Master with a routing rule, bound the Master to a widget and sent a message. The reply came back into the embedded widget after the Master selected the Worker.

M7.v1 improved the experience soon after. Token-by-token streaming landed on 27 May 2026 and the broader streaming work was completed in June. The widget could show the answer as it arrived. On 7 Jun 2026, the Worker streaming path and reusable ChatBar primitives were recorded as complete. The SDK also supported a verified-identity login path for known shoppers.

The chat could render rich card content as a core message type by the project boundary. The record does not establish that cards appeared in the 27 May demo bar, so I leave them outside that first acceptance path.

Seeing the run

Crossword persisted messages and a catalog of 29 trace-event types. The conversations area provided a workspace inbox, transcript detail and run traces. The trace viewer showed the route through the system, including Master and Worker activity, model calls and tool calls. An FDE could move from a shopper's conversation into the run that produced a specific turn.

By the time the Crossword.ai project closed on 20 Jul 2026, the dashboard was served at app.crossword.ai and the core merchant and shopper surfaces were in place for our team to operate.
