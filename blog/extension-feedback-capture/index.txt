15:T1444,<p>People can now submit feedback from the Crossword widget and from the Chrome extension, with a screenshot and a short comment attached. The report reaches the team with the conversation and recent run context needed to look at what happened. The dashboard workflow for reviewing those reports is in the feedback-status post. This post is about capture.</p>
<p>The extension path is for the person who has the extension installed: our team, a customer&#39;s team or a tester. It is not a shopper button. The widget path is a channel setting. When Widget feedback is on, Share feedback appears in the widget&#39;s header or its more menu, depending on the layout. When it is off, that entry stays hidden.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/extension-feedback-capture/01-widget-feedback-configuration.png" alt="Widget feedback is enabled from a channel's Configuration tab." /><figcaption>Widget feedback is enabled from a channel's Configuration tab.</figcaption></figure></p>
<h2 id="capture-starts-where-the-problem-is">Capture starts where the problem is</h2><p>In the widget, pressing Share feedback opens a capture layer. The reporter drags a box over the page, and Crossword prepares that region as a screenshot. There is no browser permission prompt interrupting the action. The capture code and the feedback sheet load only after the first press, so channels that do not use the reporter do not download that part of the widget.</p>
<p>The Share feedback sheet opens with the screenshot attached. The reporter can enter an email, write an optional note and add more images. A report supports up to three images. Each image can be opened in a larger view before the report is sent. After Send completes, the sheet shows a thank-you state, and the email is remembered for the next report. On a first submission from the extension, name and email are collected once and remembered. There is no password.</p>
<p>In the Chrome extension, Share feedback is available from the extension&#39;s own menu, next to Expand. Pressing it starts the same report: a screenshot, comments and the reporter&#39;s email, so the person is identifiable. The person giving feedback from the extension is the one who has it installed, which is independent of any shopper login the widget may have.</p>
<h2 id="a-real-picture-of-the-tab-from-the-extension">A real picture of the tab, from the extension</h2><p>The Chrome extension takes a real picture of the visible tab and crops it to the box the reporter drew. That preserves the page as the person saw it, including product imagery that can be difficult to rebuild from the document alone.</p>
<p>The extension path is prompt-free and has deliberate guards. It only responds during real user activation, so page code cannot trigger a tab capture on its own. It also checks that the same tab is still active when the picture returns. If the person switches tabs during capture, Crossword discards the result instead of attaching pixels from the wrong tab.</p>
<p>Sensitive areas are covered before the cropped picture becomes part of the report. Password fields, <code>cc-*</code> fields, elements marked with <code>[data-cc-mask]</code> and frames from another origin are covered in gray. The result follows the same hiding rules as Crossword&#39;s document painter.</p>
<p>When a tab picture is unavailable, Crossword falls back to rebuilding the selected area from the page&#39;s DOM. This path works without the extension, and it also takes over if tab capture fails. An image that is still loading after four seconds is left blank, so a slow image costs one image in the screenshot, not the entire report. Cross-origin product images can pass through Crossword&#39;s guarded image proxy when the browser cannot read them directly.</p>
<p><figure class="article-figure"><img src="/cw-draft-13ec83eda14bc2bc/media/extension-feedback-capture/02-feedback-report-activity.png" alt="A feedback report keeps the screenshot, note and activity together." /><figcaption>A feedback report keeps the screenshot, note and activity together.</figcaption></figure></p>
<h2 id="context-for-the-team">Context for the team</h2><p>While widget feedback is enabled, a small recorder keeps recent transport event types, console errors and widget UI events. It also tracks the last run shown in the conversation. The recorder does not keep message text, card payloads or field values in those event buffers.</p>
<p>When the report is submitted, the server connects it to the conversation and resolves the recent runs. The report can include the last run and up to ten recent top-level runs, along with page, device and widget details. The team can inspect those details beside the screenshot and the note.</p>
<p>Reports land on the Widget feedback page in the dashboard, grouped so the team can work through them by customer. The team updates their status there, including the path that asks before emailing a reporter when a report is marked Incorporated. Only the Crossword team moves items. The customer can see the status and the team&#39;s response. That operating view is described in the feedback-status post.</p>
